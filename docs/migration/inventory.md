## Explicit parity hazards (do not silently repair during translation)

- Counterparty grouping happens on cpty_lei **before** the blank-LEI fallback assignment. All blank LEIs may therefore collapse; same-source ties lack a secondary sort. Rating max_defined semantics require fixtures (mp/transform/txfm_counterparty_hierarchy.mp:41).
- SCD detection compares only eight attributes. Close-old SQL selects every ID in current staging batch, not just UPDATE records; no checked-in graph writes STG_COUNTERPARTY_RAW. UNCHANGED port is unused; MISSING is file-only; change_type is not declared in conformed DML (mp/load/ld_counterparty_tdw.mp:55; mp/load/ld_counterparty_tdw.mp:102; dml/counterparty_record.dml:33).
- Trade counterparty reader is unused; Murex/Summit normalizers do not derive asset_class. Calypso staging column mapping references feed_id absent from trade_record_t; Murex/Summit staging mappings are unspecified (mp/transform/txfm_trade_enrichment.mp:59; mp/transform/txfm_trade_enrichment.mp:125; mp/transform/txfm_trade_enrichment.mp:163; mp/load/ld_trades_tdw.mp:68; dml/trade_record.dml:10).
- FX lookup matches base currency only, not quote/date/source; missing FX falls back to unchanged amounts (positions use rate 1). Trade MV conversion uses notional currency rather than market-value currency. Position price lookup uses raw rather than validated prices (mp/transform/txfm_trade_enrichment.mp:210; mp/transform/txfm_position_aggregation.mp:68; mp/transform/txfm_position_aggregation.mp:94).
- Stale VALID prices satisfy both quality predicates; partition multi-match semantics are not documented. Price join key is instrument_id only; previous-file missing is warning. No curve interpolation or volatility validation component exists (mp/transform/txfm_market_data_validation.mp:37; mp/transform/txfm_market_data_validation.mp:46; mp/transform/txfm_market_data_validation.mp:79).
- Graph file properties use pipe delimiters/headers while DML fields declare comma delimiters. Capture actual runtime serialization, null/blank and decimal behavior before choosing precedence (dml/trade_record.dml:12; mp/transform/txfm_trade_enrichment.mp:27).
- Position reformat copies raw fields into a differently shaped enriched record; dv01 is summed downstream but is not declared in position_raw_t. Current-counterparty SELECT projects fewer fields than counterparty_conformed_t. Validate actual runtime mapping/default behavior rather than filling undeclared values (dml/position_record.dml:10; dml/position_record.dml:37; mp/transform/txfm_position_aggregation.mp:47; mp/transform/txfm_position_aggregation.mp:109; mp/load/ld_counterparty_tdw.mp:42; dml/counterparty_record.dml:33).
