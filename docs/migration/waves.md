## Critical path and safe splitting

1. Missing extracts + input snapshots + deployed warehouse definitions are the first blocker; no row-count match can prove lifecycle or SCD2 semantics without before/after state.
2. Resolve shared business-date/as-of/batch and file serialization/FX contracts, then market load/audit foundation. Counterparty source/hierarchy discovery can proceed alongside market work, but SCD2 requires missing staging evidence.
3. Counterparty state → trade lifecycle → position snapshot is the actual load critical path (scripts/run_daily_batch.ksh:163). Preserve that executable ordering initially; optimizing to the weaker dependency diagram is a separate behavior change.
4. Market-only intraday can be a smaller parity slice, **not** evidence that positions are revalued. It still needs all four feeds, MCR_LOAD_AUDIT and repeat-refresh semantics (scripts/run_intraday_refresh.ksh:43; mp/load/ld_market_data_tdw.mp:97).
5. Integration sign-off requires real persisted history and audited baseline exports, not synthetic row counts alone. Procedure internals may expand scope; wave sizes remain provisional until those arrive.

Split work by stable source/target contracts, not just graph filenames: platform team owns ingestion/file handoffs/scheduling; relational work owns explicit transforms; warehouse work owns hidden procedures/DDL and temporal transactions. These are proposed work boundaries, not verified team ownership. Maintain a separate decision log for discovered defects; the inventory records hazards without changing legacy behavior.
